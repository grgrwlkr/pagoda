# Фича: Панель тредов справа от основного чата

## Описание

Сейчас ответы в тредах видны в основном канале. Необходимо реализовать следующее поведение:
1. Ответы в тредах должны быть видны только если тред раскрыт (открыт в панели)
2. Треды должны открываться в отдельной панели справа от основного чата (правая панель становится отдельным чатом для треда)

## Текущее состояние

### Как работает сейчас:
- В `message_list.go` есть контейнер `#thread-{id}` (строки 160-163), который изначально пустой
- При клике на кнопку "Reply" ответы загружаются через HTMX в этот контейнер прямо в списке сообщений
- Ответы отображаются в основном канале под родительским сообщением
- Есть отдельная страница `/message/:id/thread` для просмотра треда на полной странице (будет удалена)

### Структура layout:
- Левая панель: Sidebar (workspaces, channels, DMs)
- Центральная панель: Основной контент (сообщения канала)
- Правая панель: `#right-panel` (сейчас скрыта на мобильных, видна на lg+ экранах, но пустая)

## Требования к реализации

### 1. Скрытие ответов в основном канале
- Ответы в тредах НЕ должны отображаться в основном канале по умолчанию
- Контейнер `#thread-{id}` должен оставаться пустым до явного открытия треда
- В основном канале должен отображаться только счётчик ответов (если есть)

### 2. Панель тредов справа
- При клике на сообщение с ответами (или кнопку "Reply") должен открываться тред в правой панели
- Правая панель должна содержать:
  - Заголовок треда (родительское сообщение или превью)
  - Список ответов в треде
  - Форму для добавления нового ответа
  - Кнопку закрытия панели
- Панель должна быть независимым чатом с собственной прокруткой
- Панель должна обновляться через WebSocket при новых ответах в треде

### 3. Поведение панели
- Одновременно может быть открыт только один тред
- При открытии нового треда предыдущий закрывается
- Панель можно закрыть вручную (кнопка закрытия)
- На мобильных устройствах панель может открываться как overlay/modal

## Corner Cases

### 1. Открытие треда
- **Случай 1.1**: Пользователь кликает на сообщение без ответов (ReplyCount = 0)
  - Должна открыться пустая панель треда с формой для первого ответа
  - Родительское сообщение должно отображаться в панели

- **Случай 1.2**: Пользователь кликает на сообщение с ответами (ReplyCount > 0)
  - Должна открыться панель с родительским сообщением и всеми ответами
  - Ответы должны быть отсортированы по времени создания (ASC)

- **Случай 1.3**: Пользователь кликает на кнопку "Reply" в основном канале
  - Если панель закрыта - должна открыться панель треда для этого сообщения
  - Если панель открыта для другого треда - должна закрыться и открыться для нового треда
  - Если панель уже открыта для этого треда - панель остаётся открытой
  - Фокус должен быть на форме ответа в панели

- **Случай 1.4**: Пользователь открывает тред, который уже открыт
  - Не должно происходить дублирования панели
  - Панель должна оставаться открытой (без перезагрузки)

### 2. Закрытие треда
- **Случай 2.1**: Пользователь закрывает панель через кнопку закрытия
  - Панель должна скрываться
  - Состояние треда (прокрутка, открытые формы) не сохраняется

- **Случай 2.2**: Пользователь открывает другой тред
  - Предыдущий тред закрывается
  - Новый тред открывается в той же панели

- **Случай 2.3**: Пользователь переключается на другой канал
  - Панель треда должна закрываться (тред относится к другому каналу)

### 3. Добавление ответов
- **Случай 3.1**: Пользователь добавляет ответ в тред через панель
  - Ответ должен появиться в панели треда
  - Счётчик ответов в основном канале должен обновиться
  - Ответ НЕ должен появиться в основном канале

- **Случай 3.2**: Другой пользователь добавляет ответ в открытый тред
  - Ответ должен появиться в панели треда через WebSocket
  - Счётчик ответов в основном канале должен обновиться

- **Случай 3.3**: Пользователь кликает "Reply" в основном канале для закрытого треда
  - Панель треда должна открыться
  - Ответ должен быть создан и отображён в панели
  - Ответ НЕ должен появиться в основном канале
  - Счётчик ответов должен обновиться

### 4. WebSocket события
- **Случай 4.1**: Новый ответ в открытом треде
  - Событие `message_new` с `thread_id` должно обновить панель треда
  - Ответ должен появиться в панели без перезагрузки
  - События для других тредов или основного канала не должны влиять на открытую панель

- **Случай 4.2**: Редактирование ответа в открытом треде
  - Событие `message_edited` должно обновить конкретное сообщение в панели

- **Случай 4.3**: Удаление ответа в открытом треде
  - Событие `message_deleted` должно удалить сообщение из панели
  - Счётчик ответов должен обновиться

- **Случай 4.4**: Удаление родительского сообщения треда
  - Панель треда должна закрыться
  - Все ответы в треде должны быть удалены (каскадное удаление или мягкое удаление - зависит от бизнес-логики)
  - Событие `message_deleted` должно быть отправлено для родительского сообщения

### 5. Множественные треды
- **Случай 5.1**: В канале несколько сообщений с ответами
  - Каждое сообщение должно показывать свой счётчик ответов
  - Клик на любое сообщение открывает соответствующий тред в панели

- **Случай 5.2**: Пользователь быстро переключается между тредами
  - Панель должна корректно обновляться без "мерцания"
  - Предыдущие данные не должны "просачиваться" в новый тред

### 6. Права доступа
- **Случай 6.1**: Пользователь не является членом канала
  - Не должен иметь возможности открыть тред
  - Кнопка "Reply" не должна отображаться

- **Случай 6.2**: Пользователь потерял доступ к каналу во время просмотра треда
  - Панель треда должна закрыться
  - Должно отображаться сообщение об ошибке доступа

### 7. Производительность
- **Случай 7.1**: Тред с большим количеством ответов (100+)
  - Панель должна загружать ответы постепенно (пагинация или виртуализация)
  - Первоначальная загрузка должна быть быстрой

- **Случай 7.2**: Одновременное открытие нескольких тредов разными пользователями
  - Каждый пользователь видит только свой открытый тред
  - WebSocket события должны корректно маршрутизироваться

### 8. UI/UX
- **Случай 8.1**: Узкий экран (мобильное устройство)
  - Панель может открываться как overlay/modal поверх основного чата
  - Или панель может занимать весь экран с кнопкой "Назад"

- **Случай 8.2**: Широкий экран (десктоп)
  - Панель открывается справа, основной чат остаётся видимым
  - Обе панели должны иметь независимую прокрутку

- **Случай 8.3**: Пользователь прокручивает основной канал во время открытого треда
  - Прокрутка основного канала не должна влиять на прокрутку панели треда
  - И наоборот

### 9. Состояние формы
- **Случай 9.1**: Пользователь начал вводить ответ, но закрыл панель
  - Введённый текст теряется (не сохраняется)
  - При повторном открытии форма пустая

- **Случай 9.2**: Пользователь отправляет ответ, но происходит ошибка
  - Ошибка должна отображаться в панели треда
  - Форма не должна очищаться (чтобы пользователь мог повторить попытку)

### 10. Интеграция с существующим функционалом
- **Случай 10.1**: Удаление старого функционала тредов
  - Страница `/message/:id/thread` должна быть удалена
  - Handler `MessageThread` должен быть удалён
  - Route `MessengerMessageThread` должен быть удалён
  - Компонент `pkg/ui/pages/messenger/thread.go` должен быть удалён
  - Все ссылки на старую страницу треда должны быть удалены

- **Случай 10.2**: Реакции на сообщения в треде
  - Реакции должны работать в панели треда так же, как в основном канале
  - WebSocket события реакций должны обновлять панель

### ⚠️ Требует уточнения:

1. **Поведение при переключении канала**
   - Вопрос: Должна ли панель треда закрываться при переключении канала?
   - Решение: Да, тред относится к конкретному каналу, поэтому панель должна закрываться

2. **Сохранение состояния формы**
   - Вопрос: Должен ли введённый текст сохраняться при закрытии панели?
   - Решение: Нет, текст теряется (как в большинстве мессенджеров)

3. **Пагинация ответов**
   - Вопрос: Нужна ли пагинация для тредов с большим количеством ответов?
   - Решение: Да, для тредов с 50+ ответами нужна пагинация или виртуализация

4. **Индикатор непрочитанных ответов**
   - Вопрос: Нужен ли индикатор непрочитанных ответов в закрытом треде?
   - Решение: Не входит в текущую фичу, но может быть добавлено позже

5. **Удаление родительского сообщения**
   - Вопрос: Как обрабатывать удаление родительского сообщения - каскадное удаление всех ответов или мягкое удаление?
   - Решение: Зависит от бизнес-логики проекта. В документе указано, что ответы должны быть удалены, но конкретный механизм (каскадное/мягкое удаление) определяется при реализации.

6. **Фильтрация WebSocket событий**
   - Вопрос: Как фильтровать WebSocket события для панели треда?
   - Решение: Клиент должен проверять `thread_id` в событии и обновлять панель только если событие относится к открытому треду. События основного канала (без `thread_id`) не должны обновлять панель треда.
