# Исправление корневого пути

## Проблема
Пользователь все еще видит главную страницу Pagoda вместо workspace мессенджера.

## Выполненные исправления

### 1. Удален Pages handler
- ✅ Удален файл `pkg/handlers/pages.go`
- ✅ Удален файл `pkg/handlers/pages_test.go`
- ✅ Исправлен тест в `pkg/handlers/handlers_test.go`

### 2. Проверена регистрация handlers
Регистрируются только:
- `*handlers.Auth` - аутентификация
- `*handlers.Messenger` - мессенджер (регистрирует `GET "/"` → `RootRedirect`)
- `*handlers.WebSocket` - WebSocket соединения

### 3. Проверен корневой путь
- ✅ `Messenger.RootRedirect` регистрируется на `GET "/"`
- ✅ `RootRedirect` проверяет аутентификацию и перенаправляет:
  - Неавторизованных → `/user/login`
  - Авторизованных → первый workspace или список workspace

## Текущее состояние

При запросе к `http://localhost:8000/`:
- Неавторизованные пользователи → перенаправление на `/user/login` ✅
- Авторизованные пользователи → перенаправление на workspace ✅

## Возможные причины проблемы

1. **Кэш браузера** - браузер может показывать закэшированную версию старой страницы
   - **Решение**: Очистить кэш браузера (Ctrl+Shift+Del) или открыть в режиме инкогнито

2. **Старый процесс сервера** - может работать старая версия сервера
   - **Решение**: Убедиться, что старый процесс остановлен и запущен новый

3. **Порядок регистрации** - хотя маловероятно, но порядок может влиять
   - **Текущий порядок**: Auth → Messenger → WebSocket
   - Messenger регистрирует `GET "/"` первым в своем `Routes()`
